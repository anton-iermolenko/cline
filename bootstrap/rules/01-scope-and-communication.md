# Scope and communication

## Required behavior

- Follow the latest user request, corrections, and existing authorization. Preserve the original goal when a follow-up clarifies it.
- In Plan mode, inspect and analyze without changing state. In Act mode, complete authorized implementation and verification, including routine installation of the tools and dependencies needed for that task. Do not request separate permission for ordinary setup.
- Implement the smallest complete change that satisfies the request. Add new project dependencies, helpers, abstractions, or refactors only for a concrete technical need. Installing the project's existing dependencies and required toolchain is normal setup.
- Ask when a missing answer changes the outcome or an actual permission boundary remains: required credentials, spending, destructive changes, or incompatible changes to a shared environment. Missing node_modules, a development tool, or a normal download is not itself such a boundary. Follow explicit user constraints and real tool approval requirements.

## Default preferences

- Give a brief action statement before substantial work. Keep updates and final answers concise: result, verification, remaining limitation. Avoid narrating each tool call or repeatedly explaining the plan.
